# 🌿 AeroSage AI

### Predict Pollution. Protect People. Breathe Smarter.

**AeroSage AI** is a Generative-AI-powered environmental health assistant that helps families and communities understand urban air pollution and make healthier everyday decisions. Instead of only displaying an AQI number, it turns air-quality data into practical guidance for outdoor activity, indoor air quality, family safety and sustainable living.

## Problem statement

Urban air pollution (for example winter smog in Indian cities) is hard for ordinary people to act on: AQI numbers are shown without context, pollutant jargon is confusing, and advice rarely reflects who is at risk (children, older adults, outdoor workers). AeroSage AI explains the data, says _why_ each recommendation helps, and is explicit about uncertainty.

## Key features

- **Live air quality** – city search, AQI (India/CPCB breakpoints, approximated from PM2.5 and PM10), pollutant readings, 3-day history and 2-day forecast.
- **Daily planner** – the cleanest outdoor hours in the next 24 h and tailored advice for everyone, children, older adults and outdoor workers.
- **AI assistant** – Google Gemini answers questions using the current readings. Replies are labelled **AI-generated by Gemini**; when Gemini is unavailable the app shows clearly labelled **basic guidance, not AI-generated** instead.
- **Indoor air** – ventilation advice, purifier sizing (AHAM rule of thumb) and low-cost fixes.
- **Impact calculators** – commute, reusable-vs-disposable and appliance savings with editable, clearly-labelled assumptions.
- **Family mode** – household profiles (device storage, or Supabase when configured) and a printable safety report.
- **Demo mode** – synthetic data, always labelled _DEMO MODE – synthetic data_, used only when the user chooses it.

## Data accuracy and safety

- Air data come from Open-Meteo (CAMS atmospheric model), **not ground sensors**. Check official CPCB/SAFAR/state sources for regulatory readings.
- AQI is a CPCB-style **approximation**: only PM2.5 and PM10 sub-indices are used, from a trailing 24 h average that requires at least 16 valid hourly values (CPCB rule). Missing data yield "Unavailable", never an invented value.
- AeroSage AI is **not a medical or diagnostic tool**. Recommendations are general information; users with symptoms are told to consult a qualified professional.

## Architecture

```text
Browser (React + Vite, Vercel)
        │  fetch /api/*
        ▼
Express API (Render) ── helmet · CORS allow-list · rate limiting · input validation
        ├── Open-Meteo Geocoding + Air Quality   (10-minute in-memory cache)
        ├── Google Gemini (server-side key, retries, timeout, labelled fallback)
        └── Supabase (optional, service key only on the server, RLS enabled)
```

```text
aerosage/

│   ├── index.js        # entry point (npm start)
│   ├── app.js          # createApp(): routes, security middleware, dependency injection

│   ├── assistant.js    # system prompt, Gemini client with retries, fallback guidance
│   ├── validation.js   # request sanitising (city, context, profile, history, UUIDs)
│   ├── family.js       # Supabase-backed family profile routes
│   └── demo.js         # synthetic demo data

│   ├── components/     # pages and UI pieces (charts are lazy-loaded)
│   ├── hooks/useAqi.js # data loading with stale-request cancellation
│   └── lib/            # AQI helpers, API client, storage, calculators
├── tests/
│   ├── server/         # API, chat/Gemini, family and AQI-maths tests
│   └── client/         # component, workflow, accessibility, hook and library tests

```

## Local development

Prerequisites: Node.js 18 or later and npm to run the app. **Running the test suite needs Node.js 22.12 or later** (a Vitest 5 requirement; Vitest is a dev-only tool and is never run on Vercel or Render).

```bash
npm install
cp .env.example .env     # then fill in your own values (never commit .env)
npm run server           # API on http://localhost:8787
npm run dev              # frontend on http://localhost:5173 (proxies /api to the API)
```

### Environment variables

| Variable               | Where    | Purpose                                                              |
| ---------------------- | -------- | -------------------------------------------------------------------- |
| `GEMINI_API_KEY`       | backend  | Gemini key (server only). Without it, labelled fallback guidance is used |
| `GEMINI_MODEL`         | backend  | Defaults to `gemini-2.5-flash`                                       |
| `PORT`                 | backend  | Defaults to `8787` (Render sets it)                                  |
| `CORS_ORIGIN`          | backend  | Comma-separated allowed origins, e.g. your Vercel URL. Empty = allow any (local dev only) |
| `SUPABASE_URL`         | backend  | Optional, enables cloud family profiles                              |
| `SUPABASE_SERVICE_KEY` | backend  | Optional, server-side only                                           |
| `AQI_CACHE_TTL_MS`     | backend  | Optional cache lifetime, default 600000                              |
| `VITE_API_URL`         | frontend | API base URL on Vercel; leave unset locally                          |

Never put the Gemini or Supabase keys in frontend code or `VITE_*` variables.

## API

| Method | Endpoint                       | Description                                                              |
| ------ | ------------------------------ | ------------------------------------------------------------------------ |
| GET    | `/api/health`                  | Status plus `features: { gemini, supabase }` booleans (no secrets)       |
| GET    | `/api/aqi?city=Kolkata`        | Live AQI, pollutants, hourly series. `404` unknown city, `502` upstream failure (`canDemo: true`) |
| GET    | `/api/aqi?city=Kolkata&demo=1` | Synthetic demo data                                                      |
| POST   | `/api/chat`                    | `{ message, history?, context?, profile? }` → `{ text, ai, source: "gemini" \| "fallback", note? }` |
| GET    | `/api/family?device=UUID`      | List profiles (`enabled: false` when Supabase is not configured)         |
| POST   | `/api/family`                  | `{ device, name, type }`, max 20 profiles per device                     |
| DELETE | `/api/family/:id?device=UUID`  | Delete a profile                                                         |

Errors are always JSON (`{ error }`). Rate limits: 120 requests/min/IP for the API and 15 messages/min/IP for `/api/chat` (`429` when exceeded); `/api/health` is never limited.

## Testing

```bash
npm test                # all tests (backend + frontend)
npm run test:server     # backend only
npm run test:client     # frontend only
npm run test:coverage   # with coverage
npm run lint            # ESLint, including jsx-a11y accessibility rules
npm run format:check    # Prettier
npm run check           # lint + tests + production build
```

Tests never call real external services and need no API keys: Open-Meteo, Gemini and Supabase are mocked through an injectable `fetch`. They cover AQI maths at every CPCB breakpoint, missing/invalid data, validation and prompt-sanitising, Gemini success/retry/timeout/rate-limit/blocked/empty/fallback paths, rate limiting, CORS, error responses, family storage, and the React workflows (search, loading/error/empty states, chat, family profiles, calculators, navigation focus) with an **axe-core scan of every page**. Colour contrast is verified by calculation against the palette because jsdom has no rendering engine.

## Accessibility

Targets WCAG 2.2 AA: skip link and landmarks, one `h1` per page that receives focus on navigation, updated page titles, polite live-region announcements for loading/results/errors, labelled form controls, visible focus indicators, 4.5:1 text contrast, AQI conveyed by text and category list (never colour alone), chart text alternatives plus data tables, `prefers-reduced-motion` support and 24 px+ touch targets. Automated checks cannot replace manual testing with a screen reader.

## Deployment

**Frontend – Vercel:** import the repo, framework Vite, build `npm run build`, output `dist`, set `VITE_API_URL=https://aerosage-api.onrender.com`. `vercel.json` also adds basic security headers.

**Backend – Render:** `render.yaml` defines the service (Node 20, build `npm install`, start `npm start`, health check `/api/health`). Set `GEMINI_API_KEY`, `CORS_ORIGIN=https://aerosageai-six.vercel.app`, and optionally the Supabase variables in the Render dashboard. Pushing to `main` redeploys both services automatically.

## Known limitations

- AQI uses PM2.5 and PM10 only and modelled data; it can differ from official station readings.
- Render's free tier sleeps when idle, so the first request can take several seconds.
- The AQI cache and rate limiter are in memory, per instance.
- Family profiles are keyed by an anonymous device ID, not a user account: anyone holding the ID can read or delete those profiles.
- Emission and cost factors in the calculators are editable placeholders, not official figures.
- Not manually tested with real screen readers or on physical devices.
