# 🌿 AeroSage AI

### Smart Environmental Health Assistant · Smarter Air. Healthier Living.

**AeroSage AI** is a Generative-AI-powered environmental health assistant that helps families and communities understand urban air pollution and make healthier everyday decisions. Instead of only showing an AQI number, it explains the data, says _why_ each recommendation helps, and is explicit about uncertainty.

## Problem statement

Urban air pollution (for example winter smog in Indian cities) is hard for ordinary people to act on: AQI numbers come without context, pollutant jargon is confusing, and advice rarely reflects who is at risk (children, older adults, outdoor workers). AeroSage AI turns air-quality data into plain-language, practical decisions.

## Key features

- **Air-quality dashboard** – city search, an _estimated_ CPCB-style AQI, six pollutants with units and sub-indices, a past-3-day trend and a 2-day forecast, and a "how was this calculated" panel.
- **Data transparency** – every screen says whether data is a **model estimate** or **synthetic demo data**, shows the provider, city, model time and retrieval time, and keeps **observed (model) values and forecasts visually and textually separate**.
- **Smart refresh** – automatic re-check every 15 minutes while the tab is visible, a manual _Refresh now_ button, last-updated and stale indicators, and request cancellation. The last valid reading is kept (and labelled **stale**) if the provider is temporarily unavailable.
- **AI assistant (Google Gemini)** – answers using only what the dashboard shows. Replies are labelled **AI-generated by Gemini**; when Gemini is unavailable you get clearly labelled **basic guidance, not AI-generated**.
- **Daily planner** – the cleanest forecast hours and tailored advice for everyone, children, older adults and outdoor workers.
- **Indoor air**, **environmental-impact calculators** (editable assumptions) and **family profiles** with a printable safety report.
- **Demo mode** – synthetic data, always labelled, used only when the user chooses it.

## How the AQI is estimated

The app computes an **estimated** Indian AQI following the CPCB National AQI method, from CAMS model data:

| Pollutant         | Averaging used                    | Unit used for CPCB breakpoints |
| ----------------- | --------------------------------- | ------------------------------ |
| PM2.5, PM10       | 24-hour mean                      | µg/m³                          |
| NO₂, SO₂          | 24-hour mean                      | µg/m³                          |
| O₃                | highest 8-hour running mean in 24 h | µg/m³                        |
| CO                | highest 8-hour running mean in 24 h | **mg/m³** (converted from µg/m³) |

- A pollutant counts only when at least **16 of the last 24 hourly values** are valid (CPCB data-coverage rule); otherwise it is left out, never invented.
- **Overall AQI = the highest sub-index.** It is reported only when a particulate (PM2.5 or PM10) sub-index exists. With three or more pollutants the basis is **full**; with fewer it is shown as **partial** and labelled so.
- Units are **read from the provider response** and converted (mg/m³ → µg/m³); unsupported units (e.g. ppb) are rejected rather than guessed.
- Results are always called **estimates**: inputs are model values, not station readings, and CPCB's NH₃ and Pb are not available. Official figures come from CPCB/SAFAR/state monitoring stations.
- The open-ended "Severe" band's upper end follows the width of the previous band (this reproduces CPCB-style caps of 380 for PM2.5 and 510 for PM10); results are capped at 500.

AeroSage AI is **not a medical or diagnostic tool**. Recommendations are general information; people with symptoms are told to consult a qualified professional.

## Local development

Prerequisites: Node.js 18+ and npm to run the app. **Running the test suite needs Node.js 22.12+** (a Vitest 5 requirement; Vitest is dev-only and never runs on Vercel or Render).

```bash
npm install
cp .env.example .env     # fill in your own values; never commit .env
npm run server           # API on http://localhost:8787
npm run dev              # frontend on http://localhost:5173 (proxies /api to the API)
```

### Environment variables

| Variable               | Where    | Purpose                                                                                  |
| ---------------------- | -------- | ---------------------------------------------------------------------------------------- |
| `GEMINI_API_KEY`       | backend  | Gemini key (server only). Without it, labelled fallback guidance is used                 |
| `GEMINI_MODEL`         | backend  | Defaults to `gemini-2.5-flash`                                                           |
| `PORT`                 | backend  | Defaults to `8787` (Render sets it)                                                      |
| `NODE_ENV`             | backend  | `production` on the host: enables a startup warning if `CORS_ORIGIN` is unset            |
| `CORS_ORIGIN`          | backend  | Comma-separated allowed origins, e.g. your Vercel URL. Empty = allow any (local dev only) |
| `SUPABASE_URL`         | backend  | Optional, enables cloud family profiles                                                  |
| `SUPABASE_SERVICE_KEY` | backend  | Optional, server-side only                                                               |
| `AQI_CACHE_TTL_MS`     | backend  | Optional fresh-cache lifetime, default 600000 (10 min)                                   |
| `VITE_API_URL`         | frontend | API base URL on Vercel; leave unset locally                                              |

Never put the Gemini or Supabase keys in frontend code or `VITE_*` variables.

## API

| Method | Endpoint                       | Description                                                                                 |
| ------ | ------------------------------ | ------------------------------------------------------------------------------------------- |
| GET    | `/api/health`                  | Status plus `features: { gemini, supabase }` (no secrets)                                   |
| GET    | `/api/aqi?city=Kolkata`        | Estimated AQI, pollutants, units, sub-indices, hourly series. See below                     |
| GET    | `/api/aqi?city=Kolkata&demo=1` | Synthetic demo data (`demo: true`)                                                          |
| POST   | `/api/chat`                    | `{ message, history?, context?, profile? }` → `{ text, ai, source: "gemini"\|"fallback", note?, truncated? }` |
| GET    | `/api/family?device=UUID`      | List profiles (`enabled: false` when Supabase is not configured)                            |
| POST   | `/api/family`                  | `{ device, name, type }`, max 20 profiles per device                                        |
| DELETE | `/api/family/:id?device=UUID`  | Delete a profile                                                                            |

`/api/aqi` returns, among others: `dataType` (`model`\|`synthetic`), `provider`, `place` (with `timezone`), `current` (pollutants in µg/m³, `aqi`, `category`, `dominantPollutant`, `subIndices`, `observedAt` in city-local time and `observedAtUtc`), `units`, `aqiMeta` (`estimated`, `basis`, `pollutantsUsed`, `method`), `series` (hourly, `future` flags forecast hours), `nowIndex`, `fetchedAt`, and `stale`/`staleReason`/`staleAgeSeconds` when an older reading is served because the provider failed.

Errors are always JSON (`{ error }`): `400` bad input, `404` unknown city/route, `413` body too large, `429` rate limited (120 req/min/IP; 15 chat messages/min/IP; health is exempt), `502` provider failure (with `canDemo: true`). All API responses send `Cache-Control: no-store`.

## Reliability

- **Open-Meteo:** 8 s timeout per request, up to 2 attempts with exponential backoff for transient failures (network, timeout, HTTP 429/5xx); never retries 4xx or malformed payloads. Responses are strictly validated (timestamps, coordinates, units, negative values).
- **Caching & dedupe:** results are cached 10 minutes, identical concurrent requests share one provider call, geocoding results are remembered for a day, and a failed refresh serves the last good reading for up to 6 hours, flagged `stale`.
- **Gemini:** 15 s timeout, up to 3 attempts, exponential backoff (500 ms → 1 s, honouring `Retry-After`), a 40 s total budget, reply length bounding, and a labelled fallback for every failure mode.

## Security

Server-side secrets only; Gemini key sent in a header and never logged; a redacting logger; helmet headers; CORS allow-list; 100 kB body limit; strict whitelisting of everything sent to the AI prompt (including family names) with prompt-injection resistance; UUID validation before any Supabase query; per-IP rate limits; JSON-only errors without stack traces; `no-store` on API responses. The Vercel frontend ships an enforced **Content-Security-Policy** (`script-src 'self'`, `connect-src` limited to the API origin, `frame-ancestors 'none'`) plus HSTS and other hardening headers. `npm audit` reports 0 vulnerabilities.

## Testing

```bash
npm test                # all tests (server + client + repository invariants)
npm run test:server     # backend only
npm run test:client     # frontend only
npm run test:repo       # security / deployment / accessibility configuration invariants
npm run test:coverage   # with coverage
npm run lint            # ESLint (complexity, a11y, no-console, …)
npm run format:check    # Prettier
npm run check           # lint + format + tests + production build
```

Tests never call real services and need no keys: Open-Meteo, Gemini and Supabase are mocked through an injectable `fetch`. They cover every CPCB breakpoint for all six pollutants, unit conversion, averaging/coverage rules, response validation, geocoding, retry/backoff/timeouts, caching, request de-duplication, stale-while-error, Gemini success/failure/fallback, prompt sanitising, rate limiting, CORS, hostile input, the React user journeys (search, refresh, stale, chat, family, calculators), time-zone independence (six zones, including a DST-change day), and an **axe-core scan of every page and key state**. Colour contrast is verified by calculation against the palette because jsdom has no rendering engine.

## Accessibility

Targets WCAG 2.2 AA: skip link and landmarks, one `h1` per page that receives focus on navigation, updated page titles, polite live-region announcements (only for user-initiated updates), labelled form controls with errors linked via `aria-describedby`, visible focus indicators, 4.5:1 text contrast, AQI conveyed by text and category list (never colour alone), observed vs forecast distinguished by line style **and** text, chart text alternatives plus data tables, `prefers-reduced-motion` support and adequate touch targets. Automated checks cannot replace manual testing with a screen reader.

## Deployment

**Frontend – Vercel:** framework Vite, build `npm run build`, output `dist`, `VITE_API_URL=https://aerosage-api.onrender.com`. `vercel.json` sets the security headers and CSP (see _Known limitations_ about the CSP's API origin).

**Backend – Render:** `render.yaml` defines the service (Node 20, build `npm install`, start `npm start`, health check `/api/health`). Set `GEMINI_API_KEY`, `CORS_ORIGIN=https://aerosageai-six.vercel.app`, and optionally the Supabase variables. Pushing to `main` redeploys both services.

## Known limitations

- AQI is an estimate from model data; it can differ from official station readings and omits NH₃ and Pb.
- The CSP in `vercel.json` hard-codes `https://aerosage-api.onrender.com` in `connect-src`: if you change the API domain, update it.
- Render's free tier sleeps when idle, so the first request can take several seconds.
- The cache, in-flight de-duplication and rate limiter are in memory, per instance.
- Family profiles are keyed by an anonymous device ID, not an account: anyone holding the ID can read or delete those profiles.
- Emission and cost factors in the calculators are editable placeholders, not official figures.
- Not manually tested with real screen readers, real browsers or physical devices; live Open-Meteo and Gemini behaviour was not exercised against the real services in development.
